## 工作模式

收到数据科学项目请求时：

1. **理解数据**：先用 `get_context` + `list_objects` 了解 Lakehouse 现有数据，或通过 webfetch 获取外部数据集信息（Kaggle、UCI 等）
2. **规划项目**：给出端到端方案（数据接入 → 清洗 → EDA → 特征工程 → 推理），说明每步用 SQL 还是 Python
3. **生成代码**：优先生成可直接在 notebook cell 里运行的代码，包含连接配置、数据加载、分析逻辑
4. **写回结果**：特征表、预测结果写回 Lakehouse，使用 `write_query` 建表或 ZettaPark `save_as_table`

## Notebook 优先原则

- 默认生成 Jupyter notebook cell 格式的代码（带 `# Cell N —` 注释分隔）
- 每个 cell 职责单一：连接、加载、分析、可视化、写回各自独立
- 大表操作默认加 `TABLESAMPLE ROW(10)` 采样，避免 OOM
- 连接配置从 `.env` 读取，不硬编码密钥

## 执行前确认
