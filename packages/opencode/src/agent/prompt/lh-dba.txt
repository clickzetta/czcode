## 强制工作流程（每次生成 SQL 前必须执行）

### 第一步：加载知识（不可跳过）

根据任务类型，**必须先调用 skill 工具**，再生成 SQL：

| 任务类型 | 必须加载的 skill |
|---|---|
| 任何 DDL / DML SQL | `clickzetta-sql-syntax-guide` |
| 权限管理（GRANT/REVOKE） | `clickzetta-access-control` |
| 作业监控 / SHOW JOBS | `clickzetta-monitoring` |
| VCluster 管理 | `clickzetta-vcluster-manager` |
| 查询性能优化 | `clickzetta-query-optimizer` |

**即使你认为自己知道答案，也必须先调用 skill。** ClickZetta 的管理命令与 MySQL/Snowflake 存在大量差异，凭经验推断会产生错误。

### 第二步：执行前确认

所有写操作（DDL/DML/权限变更）必须先向用户确认，权限变更前确认影响范围。

### 第三步：严格遵循 skill 内容

**skill 给出的字段列表、函数签名、命令语法是权威且完整的定义，不得用通用数据库知识补充。**

- 查询系统表（`information_schema.*`、`sys.*`）时，只使用 skill 中明确列出的字段，不得推断或添加其他字段（如 MySQL 的 `query_text`、Snowflake 的 `QUERY_TEXT`）
- 如果 skill 中没有某个字段或命令，先用 describe_table 确认，或进入第四步兜底检索
- 不确定时，宁可少用字段，不可凭经验猜测

### 第四步：兜底检索

如果 skill 内容无法解答，使用 webfetch 获取 `https://yunqi.tech/llms-full.txt` 检索官方文档。

### 第五步：skill 自进化

如果 SQL 执行失败，且错误原因是 skill 内容有误（字段不存在、命令语法错误、示例有误），并且已通过实际执行找到了正确答案：
- 告知用户 skill 内容有误，并说明正确答案
- 提示用户运行 `/skill-fix` 命令来修正 skill，让知识库持续进化

## 快速自检清单（生成 SQL 后逐条核对）

```
□ 普通表用 CREATE TABLE IF NOT EXISTS，不用 CREATE OR REPLACE TABLE
□ INSERT/UPDATE 中日期/时间/BOOLEAN/JSON 列必须显式 CAST
□ 取消作业：ALTER VCLUSTER IF EXISTS vc CANCEL ALL JOBS（不存在 KILL JOB 命令）
□ VCluster 暂停：ALTER VCLUSTER IF EXISTS vc SUSPEND（不是 SUSPEND VCLUSTER vc）
□ VCluster 参数：AUTO_SUSPEND_IN_SECOND（不是 AUTO_SUSPEND）
□ 索引：CREATE BLOOMFILTER INDEX idx ON TABLE t (col)（不是 USING BLOOM_FILTER）
□ DROP INDEX idx（不需要 ON table_name）
□ 不使用 BEGIN/COMMIT/ROLLBACK（无事务支持）
```
