# GitHub Events 实时数据摄取项目计划

## 项目目标

开发一个 Python 项目，演示如何通过 GitHub API 获取事件数据并实时摄取到 ClickZetta Lakehouse。

## 技术方案

### 架构设计

```
┌─────────────────┐     ┌──────────────────┐     ┌─────────────────────┐
│  GitHub API     │────▶│  Python 程序     │────▶│ ClickZetta Lakehouse│
│  /events        │     │  - 轮询获取事件   │     │  - 原始数据表       │
│  - 公共事件      │     │  - 数据转换/清洗  │     │  - 动态聚合表       │
│  - 仓库事件      │     │  - 批量写入       │     │  - 查询分析         │
└─────────────────┘     └──────────────────┘     └─────────────────────┘
```

### 数据流程

1. **数据采集**: Python 脚本轮询 GitHub API (`/events` 或 `/repos/{owner}/{repo}/events`)
2. **数据处理**: 解析 JSON 事件数据，提取关键字段
3. **数据写入**: 使用 ClickZetta Python SDK 写入 Lakehouse
4. **数据查询**: 通过 Dynamic Table 实现实时聚合分析

## 实施步骤

### 阶段 1: 环境准备和表设计

#### 1.1 ClickZetta 表设计

创建两张表：

**原始事件表 (ODS 层)**:
```sql
CREATE TABLE IF NOT EXISTS github_events (
    event_id        STRING COMMENT '事件 ID',
    event_type      STRING COMMENT '事件类型 (PushEvent, IssuesEvent 等)',
    actor_login     STRING COMMENT '用户登录名',
    actor_id        BIGINT COMMENT '用户 ID',
    repo_name       STRING COMMENT '仓库名称',
    repo_id         BIGINT COMMENT '仓库 ID',
    org_login       STRING COMMENT '组织名称',
    org_id          BIGINT COMMENT '组织 ID',
    created_at      TIMESTAMP COMMENT '事件创建时间',
    payload         STRING COMMENT '原始 payload(JSON 字符串)',
    ingested_at     TIMESTAMP COMMENT '摄入时间',
    dt              STRING COMMENT '分区字段 (日期)',
    PRIMARY KEY (event_id)
)
PARTITIONED BY (dt)
COMMENT 'GitHub 公共事件原始数据表';
```

**聚合统计表 (DWS 层)**:
```sql
CREATE OR REPLACE DYNAMIC TABLE github_events_hourly
  REFRESH INTERVAL 5 MINUTE
  VCLUSTER = default_ap
COMMENT 'GitHub 事件小时级聚合统计'
AS
SELECT
    DATE_TRUNC('hour', created_at) AS hour,
    event_type,
    COUNT(*) AS event_count,
    COUNT(DISTINCT actor_login) AS unique_users,
    COUNT(DISTINCT repo_name) AS unique_repos
FROM github_events
WHERE created_at >= CURRENT_TIMESTAMP() - INTERVAL '7' DAY
GROUP BY 1, 2;
```

#### 2.2 事件处理器 (`event_processor.py`)

功能:
- 解析 GitHub 事件 JSON 数据
- 提取标准化字段
- 数据清洗和验证
- 支持的事件类型：
  - `PushEvent` - 代码推送
  - `IssuesEvent` - Issue 操作
  - `PullRequestEvent` - PR 操作
  - `IssueCommentEvent` - Issue 评论
  - `WatchEvent` - Star 操作
  - `ForkEvent` - Fork 操作
  - `CreateEvent` - 创建仓库/分支/标签

数据模型:
```python
@dataclass

    event_id: str
```

## 关键技术点

### 1. GitHub API 速率限制

- 未认证：60 次/小时
- 已认证：5000 次/小时
- 使用 ETag 机制避免重复请求
- 监控 `X-RateLimit-Remaining` 响应头

### 2. ClickZetta 写入优化

**批量插入 (推荐用于演示)**:
```python
cursor.executemany(
    """
    INSERT INTO github_events 
    (event_id, event_type, actor_login, actor_id, repo_name, repo_id, 
     org_login, org_id, created_at, payload, ingested_at, dt)
    VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, CURRENT_TIMESTAMP(), DATE_FORMAT(CURRENT_TIMESTAMP(), 'yyyy-MM-dd'))
    """,
    [event.to_tuple() for event in events]
)
```

**IGS 实时写入 (生产环境推荐)**:
```python
from clickzetta_ingestion.realtime.realtime_options import RealtimeOptionsBuilder, FlushMode

stream = conn.get_realtime_stream(
    schema='your_schema',
    table='github_events',
    operate=RealtimeOperation.CDC,  # 主键表 CDC 模式
    options=RealtimeOptionsBuilder()
        .with_flush_mode(FlushMode.AUTO_FLUSH_BACKGROUND)
        .build()
)

for event in events:
    row = stream.create_row(RowOperator.UPSERT)
    row.set_value('event_id', event.event_id)
    # ... 设置其他字段
    stream.apply(row)

stream.close()
```

### 3. 增量获取策略

```python
# 使用 ETag 缓存
headers = {'If-None-Match': etag}
response = requests.get(url, headers=headers)

if response.status_code == 304:
    # 无新数据
    return []

# 更新 ETag
etag = response.headers['ETag']

# 或者基于事件 ID 过滤
last_event_id = get_last_processed_id()
new_events = [e for e in events if int(e.id.split(':')[0]) > last_event_id]
```

### 4. 分区策略

- 按日期分区 (`dt` 字段)
- 每天一个分区，便于数据管理和查询优化
- 自动创建新分区 (通过 `DATE_FORMAT(CURRENT_TIMESTAMP(), 'yyyy-MM-dd')`)

## 风险和挑战

1. **GitHub API 速率限制**: 可能需要多个 token 或降低轮询频率
2. **数据一致性**: 需要处理重复事件和乱序到达
3. **ClickZetta 连接稳定性**: 需要实现连接池和自动重连
4. **事件 schema 变化**: GitHub 可能添加新字段，需要向后兼容
